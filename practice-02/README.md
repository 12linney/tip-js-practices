## 3. Функции, ссылки и копирование

| № | Прогноз до запуска | Фактический результат | Причина |
|---:|---|---|---|
| 1 | `5` и `23` | `5` и `23` | Оператор `+` складывает два числа, а если один операнд строка, то преобразует число в строку и склеивает: `"2" + 3` даёт строку `"23"`. Функция не приводит аргументы к «нужному» типу, поэтому `sum("2", 3)` возвращает строку, а не число `5`. |
| 2 | До исправления `undefined`, после — `16` | До исправления `undefined`, после — `16` (тип `number`) | В стрелочной функции с телом в фигурных скобках результат не возвращается автоматически. Без `return` выражение `value * value` вычисляется и отбрасывается, функция возвращает `undefined`. |
| 3 | `5` и `true` | `5` и `true` | Присваивание `const alias = product` копирует ссылку, а не объект. Обе переменные указывают на один объект, поэтому изменение `alias.stock` видно через `product`, а `===` сравнивает ссылки и даёт `true`. |
| 4 | `7`, `false`, `true` | `7`, `false`, `true` | Spread `[...products]` создаёт новый массив (`products !== copy`), но элементы в нём — те же ссылки на объекты (`products[0] === copy[0]`). Копия поверхностная, поэтому `copy[0].stock = 7` меняет и исходный объект. |
| 5 | `3 8 3` и `false` | `3 8 3` и `false` | Spread объекта создаёт новый объект, исходный `product.stock` остаётся `3`. Побеждает последнее из повторяющихся свойств: в `first` последним стоит `stock: 8`, в `second` последним идёт `...product` со `stock: 3`, поэтому он перекрывает `8`. |
| 6 | `Без названия`, `Без названия`, `null`, пустая строка | `Без названия`, `Без названия`, `null`, пустая строка | Значение по умолчанию подставляется только когда аргумент не передан или равен `undefined`. `null` и `""` — переданные значения, поэтому возвращаются как есть. |

**Исправление эксперимента 2:** в теле стрелочной функции с фигурными скобками отсутствовал `return`, и `square(4)` возвращал `undefined`. После добавления `return value * value;` функция возвращает число `16`. Исходный результат (`undefined`) и результат после исправления (`16`) зафиксированы выше.

**Копирование массива и объекта внутри него:** `[...products]` копирует только верхний уровень (новый массив), а объекты внутри остаются общими (эксперимент 4). Независимый объект создаёт отдельный spread объекта (`{ ...product }`, эксперимент 5). Поэтому при изменении записи в `task-service.js` создаются и новый массив, и новый объект этой записи.


## 4. Модель данных и функции

Задача — плоский объект `{ id, title, completed, priority }`. Правила: `id` —
положительное безопасное целое (`Number.isSafeInteger`), `title` — строка,
после `trim()` длиной 1–100, `completed` — boolean (при создании всегда `false`),
`priority` — строго `"low"`, `"medium"` или `"high"` (по умолчанию `"medium"`).

Файлы: `data.js` — только данные (`demoTasks`, `variantNumber`, `variantTasks`);
`task-service.js` — девять функций без вывода и без глобального состояния;
`main.js` — сценарии и вывод; `checks.js` — проверки.

| Функция | Успех | Ошибка |
|---|---|---|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById` | найденный объект | `undefined` |
| `getPendingTasks`, `getTaskTitles` | новый массив | — |
| `getTaskStats` | `{ total, completed, pending, progress }` | — |
| `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` | `{ ok: true, tasks }` | `{ ok: false, error }` |

**Почему id не равен индексу:** индекс — текущая позиция в массиве и меняется
при удалении соседней записи, а `id` идентифицирует задачу и остаётся прежним.
В `demoTasks` задача с `id = 4` лежит по индексу 1, поэтому `tasks[id]` вернул
бы не ту запись.  
**Почему getTaskStats возвращает число, а не строку с процентом:** число можно
использовать в расчётах и сравнениях. Округление `toFixed(1)` возвращает строку,
поэтому оно выполняется только при выводе в `main.js`.  
**Какие объекты копируются при изменении задачи:** новый массив (`map`/spread/
`filter`) и новый объект изменяемой записи (`{ ...task, ... }`). Остальные записи
переиспользуются по ссылке, но не меняются.

## 9. Вывод

как массив объектов, а логика вынесена в функции с чёткими контрактами и ES-модули.

можно вызывать из обработчика на странице. Неизменность данных проверена сравнением
